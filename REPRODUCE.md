# Воспроизведение для экспертов

Готовые материалы: [HTML-презентация](frontend/defense.html), [PDF](presentation/AR-Inspector-defense.pdf),
[четыре фото и сценарий проверки](demo/expert-photos/README.md), [архив фотографий](demo/expert-photos.zip).

## 1. Что понадобится

- Python 3.12 и Git.
- LM Studio, один раз запущенная после установки.
- Vision-модель, поддерживающая изображения и OpenAI-совместимый API. Проверенный Mac-стенд: `lmstudio-community/Qwen3.5-4B-MLX-4bit`. MLX используется только на Apple Silicon; на Windows/Linux нужна подходящая GGUF vision-сборка с визуальным энкодером. Проверки новой версии на этих ОС не выполнялись.
- Интернет для первой установки пакетов и загрузки моделей. После подготовки приложение, данные и модели работают в локальной сети.

Для одновременной работы нужны ресурсы для VLM и детектора. Скорость зависит от модели, видеокарты и настроек; приведённая конфигурация проверена на Apple Silicon.

## 2. Получить код и установить зависимости

```bash
git clone https://github.com/bot5020/AR-INSPECTOR.git
cd hack_cyber
```

macOS / Linux:

```bash
./launch.sh setup
```

Windows, PowerShell:

```powershell
.\launch.bat setup
```

Установка создаёт `.venv`, устанавливает PyTorch и зависимости, готовит веса YOLO-World и создаёт `.env` из примера. Собственная `.env` не перезаписывается. Модели и веса в Git не включены; готовить их необходимо до отключения интернета. Подробности и диагностика: [INSTALL.md](INSTALL.md).

## 3. Запустить VLM

В LM Studio скачайте vision-модель. Для проверенного Mac-варианта это `lmstudio-community/Qwen3.5-4B-MLX-4bit`.
В терминале LM Studio CLI должен быть доступен как `lms` (на Mac также `~/.lmstudio/bin/lms`, на Windows — `%USERPROFILE%\.lmstudio\bin\lms.exe`).

Для указанной Mac-модели проверены команды:

```bash
lms server start --port 8000
lms load qwen3.5-4b-mlx --identifier vlm --context-length 6144 --parallel 1 --gpu max -y
```

Для другой сборки найдите ключ через `lms ls` и замените только `qwen3.5-4b-mlx` на установленный ключ. Сохраняйте идентификатор `vlm`. Отключите thinking; приложение также отправляет соответствующие параметры. Не запускайте несколько больших моделей одновременно.

В `.env`:

```dotenv
VLM_PROVIDER=local
VLM_URL=http://127.0.0.1:8000/v1
VLM_MODEL=vlm
VLM_REASONING_EFFORT=none
```

## 4. Запустить приложение

Поскольку модель уже загружена, используйте `--no-lms`: это не позволит старому значению модели по умолчанию выбрать другую сборку.

macOS / Linux:

```bash
./launch.sh run --no-lms
```

Windows:

```powershell
.\launch.bat run --no-lms
```

- На компьютере: [http://localhost:8081/](http://localhost:8081/).
- Презентация: [http://localhost:8081/defense.html](http://localhost:8081/defense.html); готовый HTML также открывается как файл без запуска приложения.
- Учётные записи `engineer`, `master`, `admin`: пароли автоматически создаются при первом запуске. Посмотреть их можно в `data/demo-accounts.txt` или на локальной странице [http://localhost:8081/setup](http://localhost:8081/setup). Если пароль задан в `.env`, используйте его. Сам файл с паролями не публикуется.
- Статус модели и детектора: [http://localhost:8081/api/status](http://localhost:8081/api/status). Для полного стенда нужны `vlm.ready=true`, `vlm.loaded=true`, `detector.ready=true`.
- Телефон подключается к той же Wi-Fi-сети и открывает HTTPS-адрес, напечатанный при запуске. Для камеры требуется HTTPS; первичная настройка сертификата описана в [INSTALL.md](INSTALL.md).

На чистом запуске база создаётся автоматически: насос `PUMP-001`, шкаф `CAB-003`, трансформатор `TR-001`. Телеметрия организаторов уже включена в `demo/telemetry.json`. Личная база разработчиков, их анализы, пароли и полная папка материалов организаторов не требуются. Дополнительные карточки AMS зависят от отдельно предоставленных паспортов и не нужны для четырёх фото.

## 5. Воспроизвести демонстрацию

Откройте [папку с четырьмя фото](demo/expert-photos/README.md) или распакуйте архив. Карточки выбирайте вручную:

1. `PUMP-001`: фото 01 → проверить → открыть корпус насоса и проверить находку.
2. Через «Добавить снимок» добавить фото 02 в тот же осмотр. Проверить наличие обоих кадров и сохранение решения по первому.
3. Завершить осмотр; открыть полученный PDF/XLSX. При сохранении с нерешёнными находками это явно отражается в отчёте.
4. Отдельный осмотр `CAB-003`: фото 03, главные контакты КМ1, нагар и решение инженера.
5. Резервный пример `TR-001`: фото 04. Проверять бак и вводы, не принимать неподтверждённые выводы о внутренних деталях.

На демонстрацию влияют не только фотографии: общий статус включает ресурс, ТО, измерения и открытую историю. Основания разделены в интерфейсе. Для сравнения модели смотрите именно наблюдения по текущему кадру.

## 6. Проверки и ограничения

Из активированной `.venv` можно запустить серверные и клиентские проверки:

```bash
python -m unittest discover -s tests -p "test_*.py"
node --experimental-vm-modules --test tests/frontend-auth.test.mjs tests/unified-ui.test.mjs tests/view-geometry.test.mjs
```

Node.js нужен только для клиентских проверок. Для повторного прогона четырёх фотографий с VLM:

```bash
python scripts/evaluate_vision.py --cases demo/expert-photos/cases.json --runs 1 --label expert-demo
```

Результаты прогона сохраняются в `data/eval/`; рабочая база осмотров не заменяется. Для чистого стенда используйте отдельную копию проекта и не подключайте личную базу.

VLM формирует предварительные наблюдения и может ошибиться в названии узла, рамке или причине. Самооценка уверенности модели не является измеренной точностью; окончательное решение принимает инженер.
